# Эксплуатация персонального ассистента

Изменения реализованы в исходниках. Запуск новой версии и подключение рабочих
каналов — отдельные действия. Проверки разработки используют временные данные.

## Запуск и интерфейс

```sh
.venv/bin/python launch_server.py
```

Панель supervisor: `http://127.0.0.1:5002`. API: порт 5001. Ключ панели находится
в приватном `.secrets/panel.token`, если не задан `PANEL_ACCESS_TOKEN`.
Не публикуйте эти порты в интернете.

Если порт API занят старой версией, launcher завершится с диагностикой. Сначала
штатно остановите прежний процесс. Запуск нового интерфейса сам по себе не
обновляет код уже работающего API.

Для отдельного окна macOS:

```sh
.venv/bin/python macos_setup.py build
open dist/Assistant.app
```

Приложение связано с текущим расположением проекта. При переносе пересоберите его.
Закрытие окна оставляет сервер работать; остановка API доступна в панели.

## Модели

В настройках доступны прежние LM Studio/DeepSeek и реестр дополнительных
OpenAI-совместимых endpoints. Пример записи:

```json
{
  "id": "local-code",
  "model": "your-local-model-id",
  "base_url": "http://127.0.0.1:1234/v1",
  "local": true,
  "key_env": "",
  "context_tokens": 32768,
  "output_tokens": 4096,
  "tools": true,
  "enabled": true,
  "intents": ["default", "code_generation"],
  "priority": 10,
  "timeout_seconds": 120,
  "cooldown_seconds": 60,
  "input_price": 0,
  "output_price": 0,
  "daily_budget": 0
}
```

Для удаленной модели обязателен HTTPS. В `key_env` передается имя переменной
в приватном окружении, например `EXTRA_API_KEY`; сам ключ в реестр не вводится.
После изменения окружения процесс нужно перезапустить. Изменения реестра и
несекретных настроек применяются к последующим задачам без рестарта.

`intents` задает участие в автоматическом выборе; пустой список оставляет ручной
выбор. `default` обрабатывает решения без специализированной метки, в том числе
локальные приватные запросы. Среди допустимых моделей выбирается больший priority.
В панели видны наличие ключа, пауза после сбоя и резерв расходов за день UTC.

Тарифы задаются за миллион токенов в одной выбранной вами валюте. До запроса
резервируется консервативная оценка по числу байтов UTF-8 и максимально допустимому
ответу. Ошибочный HTTP-вызов тоже учитывается: его фактическая тарификация неизвестна.
Это ограничитель по настройкам, а не выписка провайдера. `daily_budget: 0`
отключает лимит. Лимиты реестра относятся к моделям реестра; прежние подключения
LM Studio/DeepSeek настраиваются отдельно.

Личная память, знания, локальные инструменты и приватная история ограничивают
выбор локальными моделями. Для этих контекстов веб-инструменты также отключены.
Для обращения к облаку или вебу используйте отдельный диалог без приватных данных.

## Проекты, знания и память

Панель и подтверждённые личные чаты MAX и Telegram используют общую память владельца.
В разделе «Привязка каналов» создайте код, отправьте показанную команду в личный
чат с ботом и подтвердите привязку в панели. Привязка памяти действует без выбора
диалога. «Запомни» и «Забудь» меняют общую запись, а раздел «Личная память»
показывает те же данные. При первом подтверждении MAX старые факты переносятся
из памяти этого чата. При совпадении поля сохраняется значение из общей памяти.
Отзыв привязки закрывает доступ чату. Общая память хранится в локальной БД,
а ответы с её контекстом используют локальную модель.

Выбор проекта находится над разделами панели. Новые диалоги закрепляются за ним;
историю нельзя незаметно переключить в другой проект. Документы и подтвержденные
заметки проекта имеют отдельную область поиска. Очистка заметок меняет будущий
контекст, но не переписывает уже сохраненные ответы.

В разделе «Знания» выберите файл и нажмите «Добавить в базу». TXT и Markdown
принимаются до 512 КБ, PDF, RTF и DOCX до 20 МБ. Для RTF и DOCX используется
встроенный конвертер macOS. Для папок укажите отдельный
абсолютный каталог в разделе «Знания». Скрытые файлы и ссылки пропускаются.
Worker обрабатывает по одному измененному файлу за итерацию, показывает ошибки,
обновляет индекс и исключает удаленные исходники. Неудачно обновленный документ
не используется как актуальный. Кнопка переиндексации повторяет извлечение.
Удаленный вручную документ watcher автоматически не возвращает.

PDF с текстовым слоем:

```sh
.venv/bin/python -m pip install -r requirements-rag.txt
```

Для сканов на macOS:

```sh
.venv/bin/python macos_setup.py build-ocr
```

После сборки задайте `RAG_OCR_ENABLED=1` в приватном `.env` и перезапустите API/worker.
Распознавание выполняет Apple Vision локально. Ограничения: исходник до 20 МБ,
обычный PDF до 200 страниц, OCR до 20 страниц, извлеченный текст до 512 КБ,
ограниченное время обработки. Зашифрованные документы нужно расшифровать заранее.
Фрагменты сохраняют строки и текстовые обозначения страниц; открытие источника
в панели показывает извлеченный текст, а не PDF-просмотрщик.

Для смыслового поиска задайте `RAG_EMBEDDING_MODEL` и локальный
`RAG_EMBEDDING_BASE_URL`; при недоступности эмбеддингов сохраняется текстовый поиск.
Для скачанного Multilingual E5 Small можно вместо HTTP указать
`RAG_EMBEDDING_LOCAL_DIR=.models/embeddings/multilingual-e5-small`. Тогда модель
вычисляет векторы на CPU прямо в процессах ассистента, без обращения к LM Studio.
В «Проверить поиск» фрагменты помечаются «по словам», «по смыслу» или обоими способами.
После смены модели эмбеддингов переиндексируйте источники.

## Каналы и общий диалог

Telegram изначально выключен. В приватной конфигурации задайте:

- `TELEGRAM_ENABLED=true`;
- `TELEGRAM_BOT_TOKEN`;
- `TELEGRAM_ALLOWED_SENDER_IDS` — разрешенные числовые sender IDs.

После рестарта в разделе «Каналы» создайте одноразовый код, отправьте команду
`/link …` соответствующему боту, проверьте sender/chat IDs в панели, подтвердите
запрос и выберите диалог. Код действует десять минут и используется один раз.
Привязка ограничена конкретной парой отправитель/чат и доступна только в личных чатах. Для MAX событие должно подтверждать тип личного диалога.
Права на команды и файлы привязка не выдает. `/unlink` или отзыв в панели
блокирует дальнейший доступ и доставку связанного контекста.

## Расписания и голос

В разделе «Расписания» доступны ежедневные и интервальные задачи, часовой пояс,
пропуск или однократная обработка пропущенного запуска. Результат остается в
панели или направляется в подтвержденный канал с выбранным общим диалогом.
Изменение/отзыв привязки отключает соответствующее расписание. Запуски без
инструментов; выполнение локальное. История находится в списке запусков и диалогах.
Кнопка «Удалить» в карточке автоматизации после подтверждения убирает расписание.
История сохраняется, задания, уже добавленные в очередь, выполняются.

Сводки, вопрос о настроении и уведомления macOS используют один координатор и
общий outbox. В панели их можно включать, выключать и удалять. Удалённый сервис
исчезает из расписаний и больше не ставит задания в очередь. Получатели и время
прежних сервисов пока берутся из приватной конфигурации. Отметка постановки
в очередь не равна квитанции доставки: ее состояние видно в запусках.

Голосовой файл из панели или разрешенного личного Telegram-чата проходит через
общую очередь и локальный ASR. MAX сохраняет существующий вход голосовых сообщений.
Временный файл панели удаляется после распознавания; расшифровка сохраняется.
Голосовой ввод панели не включает инструменты. Неудачное распознавание предлагает текст.
На голосовое сообщение в Telegram бот отправляет полный текст ответа, а затем
голосовую версию первых 600 символов. Если синтез недоступен, остается текст.

Озвучивание использует отдельное `.venv-tts` и подготовленный профиль `.voices`.
Раздел «Голос» показывает сохраненные пары «эталон + модель» из приватного
`.voices/presets.json` и позволяет прослушать привязанный пример. Кнопка выбора
сохраняет пару для последующих озвучек без перезапуска. Если пара не выбрана,
используется активный эталон и модель из `TTS_MODEL_DIR`.
В панели нажмите кнопку озвучивания, в мессенджере отправьте `/speak` для последнего
доступного ответа этому же отправителю и чату. Озвучиваются первые 600 символов;
полный текст остается доступным. При отсутствии TTS или профиля возвращается
понятное сообщение. Формат результата — MP3. Реальные отправки аудио требуют
проверки с рабочими каналами.

Для отдельной пробы XTTS-v2 используется окружение `.venv-xtts` с
`requirements-xtts.txt` и официальный локальный чекпойнт Coqui в `.models/xtts-v2`.
Модель и ее записи предназначены для некоммерческого использования по
[Coqui Public Model License](https://huggingface.co/coqui/XTTS-v2/blob/v2.0.3/LICENSE.txt).
После установки окружения и скачивания весов пример создается на CPU:

```sh
.venv-xtts/bin/python xtts_sample.py --reference reference_20261107.wav \
  --text-file .voices/generated/xtts-comparison.txt
```

Запись остается в `.voices/generated`. Образец с `preview_only: true` в
`.voices/presets.json` можно прослушать в панели без смены рабочего голоса.

## Автозапуск macOS

Сначала проверьте запуск вручную. Подготовка plist ничего не устанавливает:

```sh
.venv/bin/python macos_setup.py plist
```

Установка и удаление сервиса текущего пользователя:

```sh
.venv/bin/python macos_setup.py install
.venv/bin/python macos_setup.py uninstall
```

Установка запускает supervisor, который запускает API и worker. Используется
LaunchAgent `local.personal-assistant.supervisor`; аварийные рестарты ограничены
ThrottleInterval. Секреты в plist не записываются. Для нестандартного порта панели
используйте `macos_setup.py build --port …`; серверный порт задается конфигурацией.

## Резервные копии, экспорт и восстановление

JSON-экспорт персональных данных доступен из панели. Для полного согласованного
комплекта остановите API и worker:

```sh
.venv/bin/python backup_bundle.py create --file /path/assistant-backup.zip
```

В архив входят основная БД, память панели, стандартная старая память MAX,
состояние фоновых сервисов, исходники, аудиофайлы, стандартная `.voices` и
неизмененные индексированные оригиналы из выбранных папок. Внешнюю память укажите
через `--memory /path/personal.sqlite3`, дополнительные или внешние голосовые
каталоги — через `--artifacts /path`. Секреты, веса моделей и логи исключены.
Архив приватный (0600), ограничен 2 ГиБ и проверяется по SHA256.

Проверка/распаковка для просмотра:

```sh
.venv/bin/python backup_bundle.py extract --file /path/assistant-backup.zip --destination /new/export
```

Подготовка новой установки:

```sh
.venv/bin/python backup_bundle.py prepare-installation --file /path/assistant-backup.zip --destination /new/assistant
```

Существующий каталог не перезаписывается. В новой установке нужно создать Python
окружения, установить зависимости и настроить секреты. Старые незавершенные
запуски остановлены; расписания, фоновые сервисы, привязки и watcher выключены.
Индексированные оригиналы находятся в `restored-documents`; заново выберите
папки для наблюдения. Сырые экспорты и старые архивы могут содержать удаленные ранее
данные. Восстановление основной БД через `storage_admin.py restore` учитывает
журналы удаления документов и диалогов из текущей БД.

Очистка старых логов и аудио сначала только показывает кандидатов:

```sh
.venv/bin/python data_admin.py --days 30
# После остановки API и worker:
.venv/bin/python data_admin.py --days 30 --apply
```

Она не удаляет БД, документы, профили голоса и ключи. Удаление диалога через панель
требует завершения запуска и разрешения неопределенной доставки.

## Обновление управляющего процесса

Для самого supervisor используется отдельная процедура. Подготовьте полное дерево
новых исходников, например проверенную рабочую копию проекта:

```sh
.venv/bin/python supervisor_update.py prepare --source /path/new-source
```

Команда запускает автономные тесты, фиксирует исходные хеши и возвращает release ID.
Затем остановите автозапуск/supervisor штатным способом, убедитесь, что API и
worker завершены, и примените:

```sh
.venv/bin/python supervisor_update.py apply --release RELEASE_ID
```

Запустите новую версию и проверьте панель, health-check и worker. Если проверка
не пройдена, снова остановите процессы и выполните:

```sh
.venv/bin/python supervisor_update.py rollback --release RELEASE_ID
```

Измененные после подготовки исходники блокируют применение. Копия для возврата
и тестовый журнал находятся в приватной `.supervisor_releases`. Эта процедура
не заменяет резервное копирование данных.

## Проверки

```sh
.venv/bin/python -m unittest discover -s tests
RUN_INTENT_MODEL_TESTS=1 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python -m unittest discover -s tests -p test_intent_model.py
.venv/bin/python evaluate_assistant.py --load
.venv/bin/python tests/integration_harness.py
.venv/bin/python tests/integration_launcher.py
.venv/bin/python tests/integration_ocr.py
.venv/bin/python tests/integration_local_model.py
.venv/bin/python tests/integration_tts.py
```

Интеграционные проверки используют временные данные; OCR, модель и TTS требуют
соответствующих локальных компонентов. `evaluate_assistant.py` измеряет поиск на
четырех искусственных примерах и нагрузку хранилища. Это регрессия, а не оценка
качества ответов на ваших документах. Реальные Telegram/MAX-сценарии выполняются
отдельно после настройки и явного выбора тестовых сообщений/получателей.

## Секреты панели

После входа по ключу панель supervisor предложит создать PIN из 6–12 цифр. В разделе «Секреты» имена ключей видны сразу. Нажмите «Изменить» или «Добавить секрет» и введите PIN. Редактирование доступно пять минут. Иконка глаза показывает значение одной записи. После сохранения перезапустите API через раздел «Инфраструктура».

Панель берет исходные значения из `.env` и настроек окружения запуска. Изменения из панели хранятся в зашифрованном `.secrets/project.vault`. Ключ шифрования находится рядом в локальном файле `.secrets/vault.key`, доступном владельцу. PIN проверяется по хешу из `.secrets/vault.pin` и ограничивает доступ через панель. Секреты, заданные окружением процесса, имеют приоритет и доступны в панели только для чтения. Ключ входа панели хранится отдельно. Обычная резервная копия проекта исключает секреты.

## Ежедневная проверка сбоев

Supervisor после 04:00 по Москве раз в день проверяет сохраненные результаты и ошибки за последние сутки. При подтвержденном сбое подключения к локальной модели он пробует восстановить LM Studio и перезапускает API, когда очередь не выполняет и не доставляет задачи. После старта проверяется готовность через `/healthz`. Ручная остановка сервера откладывает проверку. Итог и идентификаторы задач отображаются в «Инфраструктуре». Другие ошибки и обнаруженные отказы требуют разбора. Тексты диалогов не копируются в отчет.
