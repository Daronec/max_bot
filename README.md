# MAX Bot — локальный ИИ-ассистент в мессенджере MAX

Бот для мессенджера **MAX**, который принимает текстовые (и голосовые) задания в чате,
передаёт их локальной языковой модели в **LM Studio / Bionic** через OpenAI-совместимый API
и возвращает готовый ответ в тот же чат. Дополнительно работает веб-интерфейс и HTTP API
на `http://127.0.0.1:5001`.

## Основные функции

- **Обработка заданий из MAX** — входящий текст сохраняется в очередь `tasks/`, отправляется
  модели и возвращается ответом на исходное сообщение. Чат определяется автоматически
  (`MAX_CHAT_ID` нужен только для ограничения одним чатом). Сообщения самого бота пропускаются,
  чтобы не возникал цикл ответов.
- **Вызовы инструментов моделью** — модель сама решает, когда искать в интернете, читать файлы
  или запускать команды; сервер выполняет инструменты и дополняет ответ.
- **Веб-доступ** (`WEB_ENABLED`) — инструменты `web_search` (поиск без API-ключа, со ссылками
  и выдержками) и `open_url` (чтение текста публичной страницы). Модели передаётся актуальная
  дата и требование проверять факты по страницам и указывать источники.
- **Файловые инструменты** (`FS_ENABLED`, только для разрешённых чатов `FS_ALLOWED_CHAT_IDS`) —
  `list_directory`, `search_files`, `read_file`, `write_file`, `edit_file`, `create_directory`.
  Работа только внутри `FS_ROOTS` (по умолчанию каталог проекта и `~/Projects`), UTF-8 до 1 МБ,
  изменение файла требует SHA256 из последнего чтения, исходная версия сохраняется
  в `.bot_file_backups/`, запись атомарная. Доступ к токенам, `.env` и служебным путям закрыт.
- **Консольные команды** (`COMMANDS_ENABLED`, `run_command`) — запуск shell-команд для
  разрешённого чата по прямой просьбе пользователя; возвращаются exit code, stdout, stderr
  и признак тайм-аута (по умолчанию 120 с, максимум 600 с, вывод до 16 000 байт).
- **Голосовые сообщения** — расшифровка речи на русском (до 5 минут / 20 МБ) локально через
  Whisper small и выполнение полученного задания.
- **Утренняя сводка** — каждый день в 08:00 по времени Mac в доверенный чат: события Календаря
  на день, просроченные напоминания и уведомления за 24 часа. Проверка вручную — команда `/summary`.
- **Пересылка уведомлений macOS** — новые уведомления «Почты», Telegram, «Календаря»
  и «Напоминаний» пересылаются в чат (проверка каждые 5 секунд, старая история пропускается).
- **Приложения и напоминания macOS** — запуск приложений по имени и создание напоминаний
  с указанным в сообщении сроком (по локальному времени Mac) с возвратом ID напоминания.
- **Устойчивость** — очередь, статусы, результаты и журнал действий (`file_actions`,
  `command_actions`) хранятся на диске и загружаются после перезапуска; при недоступности
  модели задание остаётся в очереди и повторяется; длинные ответы делятся на части до 4000 символов.
- **TLS для MAX API** — локальная цепочка `certs/max-ca.pem` (восстанавливается `setup_max_tls.py`),
  системное хранилище доверия не меняется.
- **Веб-интерфейс и API** — `http://127.0.0.1:5001`, состояние: `/api/status`; без авторизации,
  поэтому по умолчанию сервер слушает только localhost.

## Быстрый старт

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
chmod 600 .env
# Заполните .env своими значениями перед запуском.
lms server start --port 1234 --bind 127.0.0.1   # локальный сервер модели
python3 run.py                                  # запуск бота и веб-интерфейса
```

Затем откройте диалог с ботом в MAX и отправьте задание текстом или голосом.
`run_simple.py` и `server.py` запускают тот же сервер. Токен бота хранится только в локальном `.env`
и не выводится в интерфейсе и логах; его можно переопределить переменной окружения.

Примеры сообщений боту:

- «Найди последние новости о Python и дай ссылки на источники»
- «Прочитай README.md и кратко перескажи»
- «Создай файл notes.txt с текстом: Проверка доступа»
- «Запусти git status --short в проекте ~/Projects/my-project»
- «Напомни завтра в 18:00 позвонить врачу»
- `/summary` — получить утреннюю сводку сейчас

## Основные настройки

| Переменная | Назначение |
|---|---|
| `LM_BASE_URL` | адрес сервера модели, по умолчанию `http://127.0.0.1:1234/v1` |
| `LM_MODEL` | идентификатор модели в LM Studio |
| `LM_MAX_TOKENS`, `LM_TIMEOUT` | лимит ответа (4096) и время ожидания (180 с) |
| `WEB_ENABLED`, `WEB_TIMEOUT` | веб-поиск и чтение страниц |
| `FS_ENABLED`, `FS_ROOTS`, `FS_ALLOWED_CHAT_IDS` | файловые инструменты и разрешения |
| `COMMANDS_ENABLED`, `COMMAND_TIMEOUT` | консольные команды |
| `NOTIFICATIONS_ENABLED` | пересылка уведомлений macOS |
| `MAX_CHAT_ID`, `MAX_BOT_TOKEN`, `MAX_API_BASE_URL` | параметры интеграции с MAX |
| `HOST`, `PORT` | адрес и порт веб-сервера (по умолчанию 127.0.0.1:5001) |

## Безопасность

- Веб-API не имеет авторизации — не публикуйте его напрямую в интернете.
- Файловые инструменты ограничены `FS_ROOTS`; консольные команды работают с правами
  пользователя ОС и **не** являются файловой изоляцией.
- Инструменты записи и запуска не предоставляются без прямой просьбы пользователя
  и только для разрешённых чатов.

## Локальная маршрутизация намерений

`process_message` и комментарии о настроении сначала используют `intent_router`:
локальное правило → mDeBERTa → проверка локального флага API.
Локальные операции, явно запрошенный офлайн-режим, неизвестная метка,
ошибка классификатора и низкая уверенность выбирают Qwen. DeepSeek используется
только для уверенных `data_analysis`, `creative_writing`, `api_call`, `web_search`.
`LM_PROVIDER` больше не выбирает модель для этих обработчиков.

Переменные окружения:

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `ROUTER_CONFIDENCE_THRESHOLD` | `0.55` | Минимальная уверенность для DeepSeek |
| `DEEPSEEK_ENABLED` | `true` | `false` полностью отключает DeepSeek в обработчиках сообщений |
| `DEEPSEEK_COOLDOWN_SECONDS` | `60` | Пауза после ошибки API перед следующей пробной попыткой |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com/v1` | Адрес удалённого API |
| `DEEPSEEK_MODEL` | `deepseek-flash` | Удалённая модель |

Qwen использует существующие `LOCAL_LM_BASE_URL`, `LOCAL_LM_MODEL`,
`LOCAL_LM_API_KEY`. Наличие `DEEPSEEK_API_KEY` задаёт начальное разрешение
попробовать API, а не подтверждение работающей сети. При отсутствии ключа
используется Qwen. Проверок сети на каждое сообщение нет. Ошибки HTTP,
таймауты и сетевые исключения закрывают доступ на время охлаждения.
После паузы следующий кандидат пробует API; при повторном сбое снова выбирается Qwen.
Это действует независимо от старого `LM_FALLBACK_ENABLED`.

Подготовка модели (однократно, при наличии интернета):

```sh
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -c 'from transformers import pipeline; p = pipeline("zero-shot-classification", model="MoritzLaurer/mDeBERTa-v3-base-mnli-xnli", device=-1); print(p("привет", candidate_labels=["общение", "анализ данных"], hypothesis_template="Это запрос на {}."))'
```

В рабочем потоке загрузка весов и токенизатора выполняется строго с
`local_files_only=True`: сетевого скачивания нет. Один CPU pipeline разделяется
между запросами и потоками. После первой ошибки загрузки используется Qwen;
после установки зависимостей или загрузки весов перезапустите процесс бота.
Отдельные пользовательские ошибки DeepSeek не показываются:
тот же диалог со всеми результатами инструментов продолжается через Qwen.

Классификатор: `MoritzLaurer/mDeBERTa-v3-base-mnli-xnli`,
`pipeline("zero-shot-classification")`. Он сравнивает запрос с восемью
описаниями из `INTENT_DESCRIPTIONS`, используя шаблон
`This text is about {}.`. Описания служебные и заданы по-английски:
они лучше сработали на пробной русской выборке. Сам запрос подаётся
на русском без перевода. Адаптер возвращает прежние стабильные идентификаторы
намерений; код выбора Qwen / DeepSeek не изменён. Токенизатор ограничен
512 токенами, pipeline обрезает длинный запрос, сохраняя гипотезу целиком.
Дополнительная зависимость `sentencepiece` нужна для токенизатора mDeBERTa.

Используется `multi_label=False`: оценки нормализованы относительно восьми
кандидатов и не являются калиброванной вероятностью правильности. Порог
`0.55` оставлен без искусственного увеличения score; его нужно оценивать на
отдельной репрезентативной выборке реальных запросов. Классификация выполняет
NLI-сравнение с каждым кандидатом, поэтому требует больше вычислений, чем
прежний специализированный AgentIntentRouter. Неоднозначные запросы остаются
в Qwen при низкой уверенности.
Карточка модели: https://huggingface.co/MoritzLaurer/mDeBERTa-v3-base-mnli-xnli

Решения пишутся через стандартный `logging`: первые 160 символов сообщения,
метка, score, цель и причина. Состояние API и время охлаждения доступны через
существующий `routing_status()`. Тесты используют подменённый классификатор,
покрывая все восемь меток, ошибки и граничные значения независимо от кэша весов.


## Имя помощника — Агафья

Обе модели получают общую инструкцию с именем «Агафья». Обращение необязательно:
«Агафья, проанализируй данные» и «Проанализируй данные» обрабатываются одинаково.
Обращение в начале сообщения (в том числе «Привет, Агафья, ...») или после
запятой в конце убирается перед маршрутизацией и обработкой команд. Внутренние
упоминания имени в содержимом задания не заменяются. На отдельное «Агафья!»
помощник отвечает «Я здесь. Чем помочь?» без запуска инструментов.

Голосовые вложения проходят тот же путь после локального распознавания речи.
В faster-whisper передаётся словарная подсказка `hotwords="Агафья"`. Дополнительно
распознаётся обращение «Агафия» — возможный вариант записи имени распознавателем.
Исходная расшифровка сохраняется, текст самого задания не переписывается целиком.
Словарная подсказка помогает, но не гарантирует распознавание имени в любой записи.

Имя задаётся через `ASSISTANT_NAME` (по умолчанию `Агафья`), дополнительные
варианты — через `ASSISTANT_NAME_ALIASES`, разделённые запятыми (по умолчанию
`Агафия` для имени Агафья). Новые настройки применяются после перезапуска бота.
Это обработка полученных сообщений, а не постоянное прослушивание микрофона.
Получение нативного голосового зависит от того, передаст ли MAX аудиовложение боту;
если не передаёт, запись можно отправить аудиофайлом.


## Секреты и локальная конфигурация

Токены, API-ключи, идентификатор бота и приватные chat ID хранятся в `.env`
в корне проекта. `config.py` автоматически читает только этот файл через
python-dotenv до создания настроек. Значения окружения процесса имеют приоритет;
подстановки `${...}` внутри значений отключены, чтобы не менять содержимое ключей.
Чтения ключей из `.secrets/` и встроенного токена в коде больше нет.

На новой установке выполните `cp .env.example .env`, заполните значения локально
и задайте `chmod 600 .env`. В `.env.example` нет настоящих ключей и личных ID.
`.env` и его варианты исключены из Git. Отсутствующие ключи и ID по умолчанию
пусты: доступ к файловым операциям требует явного `FS_ALLOWED_CHAT_IDS`.
При изменении `.env` перезапустите работающий процесс бота.

`.env` — текстовый файл, а не шифрование. Не отправляйте его в чат или репозиторий.
Переписка, расшифровки, журналы и состояние задач остаются в прежних файлах данных:
они не являются настройками и не переносятся в `.env`.


## Тесты без личных настроек

Тесты используют синтетические ключи и ID из `tests/bot_test_support.py`,
поэтому настоящие учётные данные и `.env` для них не требуются.
Проверки реальной mDeBERTa включаются через `RUN_INTENT_MODEL_TESTS=1`
и требуют заранее скачанных весов. В обычном запуске эти проверки пропускаются.
