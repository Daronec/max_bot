# Запуск бота MAX с автоматической обработкой заданий

Токен бота и приватные настройки задаются в `.env` (шаблон — `.env.example`). Не публикуйте `.env`.

1. В LM Studio загрузите языковую модель и включите локальный сервер на порту 1234.
   Сервер можно включить командой:

   ```bash
   lms server start --port 1234 --bind 127.0.0.1
   ```

2. В каталоге проекта установите зависимости и запустите бота:

   ```bash
   python3.12 -m venv .venv
   .venv/bin/python -m pip install -r requirements.txt
   cp .env.example .env
   chmod 600 .env
   # Заполните MAX_BOT_TOKEN, MAX_BOT_ID и ID разрешённых чатов в .env.
   .venv/bin/python run.py
   ```

   Подготовьте локальные модели перед запуском: см. разделы маршрутизации и голосового ввода в README.md.

3. Откройте диалог с ботом в MAX и отправьте текст задания.
   Бот автоматически передаст его локальной модели и пришлёт ответ в этот же чат.
   Веб-интерфейс и ручная публикация результатов для этого не требуются.

Для входящих сообщений `MAX_CHAT_ID` не нужен: чат берётся из события MAX.
Если задать `MAX_CHAT_ID`, бот будет обрабатывать только этот чат.
Исходящие сообщения самого бота пропускаются, чтобы не создавать цикл ответов.

По умолчанию используется `http://127.0.0.1:1234/v1` и локальная
модель `qwen/qwen3.5-9b`. При необходимости выберите другую:

```bash
export LOCAL_LM_MODEL='идентификатор модели из LM Studio'
python3 run.py
```

Другой адрес Qwen: `LOCAL_LM_BASE_URL`; ключ локального сервера: `LOCAL_LM_API_KEY`.
Задайте их в `.env`. DeepSeek используется как опциональное усиление через локальный маршрутизатор.

По умолчанию используется OpenAI-совместимый API LM Studio с выключенным долгим
рассуждением (`LM_REASONING=off`). Лимит ответа: `LM_MAX_TOKENS` (4096).

## Интернет для модели

Веб-доступ уже включён (`WEB_ENABLED=1`). Модель сама вызывает инструменты
`web_search` (поиск) и `open_url` (чтение текста страницы и ссылок).
Напишите в MAX, например: «Найди последние новости о Python и дай ссылки на источники»
или «Прочитай https://www.python.org/ и кратко перескажи».

Поиск работает без отдельного API-ключа. Глобальные разрешения MCP в LM Studio
менять не требуется: инструменты выполняет сервер бота по запросам модели.
Поддерживаются публичные HTTP/HTTPS-страницы. Вход в аккаунты и выполнение
JavaScript не предусмотрены; для таких страниц используйте доступный текстовый источник.

Отключение интернета: `WEB_ENABLED=0 python3 run.py`.
`WEB_TIMEOUT` задаёт время ожидания сайта (20 секунд), `WEB_MAX_TOOL_ROUNDS` —
число раундов работы с инструментами на одно задание (8).

Для API MAX подготовлена локальная цепочка сертификатов `certs/max-ca.pem`.
Если требуется восстановить её, выполните `python3 setup_max_tls.py` и перезапустите
бота. Сертификаты загружаются с официального сервера Госуслуг; системные настройки
доверия не меняются. Свой CA-файл можно указать через `MAX_CA_BUNDLE`.

Если LM Studio недоступен, бот сохранит задание, сообщит о проблеме в MAX и будет
повторять обработку. При ошибке доставки готовый ответ сохраняется, а отправка
повторяется без повторного запроса к модели. После перезапуска очередь загружается
с диска. Длинные ответы отправляются частями до 4000 символов.

## Файлы для модели

Доступ нужно разрешить через `FS_ALLOWED_CHAT_IDS` в `.env`. Модель может просматривать
каталоги, искать файлы по имени, читать, создавать и изменять текстовые файлы UTF-8.
По умолчанию разрешены каталог проекта `max_bot_api` и `~/Projects` со всеми
проектами внутри. Относительные пути считаются от `max_bot_api`; для других проектов
указывайте полный путь, например `~/Projects/my-project/README.md`.

Примеры сообщений в MAX:

- «Покажи файлы в рабочей папке».
- «Прочитай файл README.md и кратко перескажи».
- «Создай файл notes.txt с текстом: Проверка файлового доступа».
- «В файле notes.txt замени Проверка на Проверено».

Перед изменением существующего файла бот читает его актуальную версию, а исходный
текст сохраняет в `.bot_file_backups/`. Если файл изменился параллельно, запись
не выполняется до повторного чтения. После сбоя уже изменявшая файлы задача
автоматически не повторяется, чтобы не дублировать правки.

Настройки в `config.py` или переменных окружения:

- `FS_ENABLED=0` отключает файловые инструменты.
- `FS_ALLOWED_CHAT_IDS` — разрешённые числовые ID чатов через запятую.
- `FS_ROOTS` — разрешённые каталоги; на macOS несколько путей разделяются `:`.
- `FS_SEARCH_ROOTS` — дополнительные каталоги для поиска имён проектов и файлов,
  по умолчанию `~/Projects`. Поиск без `path` проверяет все настроенные каталоги.
  Эта настройка не даёт права читать или менять содержимое найденных проектов.

Файловые инструменты закрывают доступ к токену, `.env`, ключам, внутренним каталогам
и резервным копиям. Через них нельзя менять код управления правами и служебные данные.
Лимит одного файла — 1 МБ.

## Консольные команды

Для чата `<ID_ВАШЕГО_ЧАТА>` включён `run_command`. Примеры:

- «Выполни команду pwd в каталоге ~/Projects/my-project».
- «Запусти git status --short в проекте ~/Projects/my-project».
- «Запусти тесты в проекте ~/Projects/my-project и верни результат».

Команды запускаются через `/bin/zsh -f` с обычными правами вашего пользователя ОС.
Рабочий каталог проверяется по `FS_ROOTS`, но это **не изоляция файловой системы**:
сама команда может обращаться к другим доступным пользователю путям и запускать
код проектов. Ограничения и резервные копии файловых инструментов не распространяются
на изменения, сделанные консольной командой. Стандартный ввод отключён.

Ответ инструмента содержит stdout, stderr, код завершения и признак тайм-аута.
По умолчанию тайм-аут — 120 секунд (максимум 600); вывод ограничен 16 000 байт.
При тайм-ауте завершается группа процессов команды. Попытка запуска записывается
до исполнения, чтобы после сбоя или перезапуска команда не выполнялась повторно
автоматически.

Настройки: `COMMANDS_ENABLED=0` отключает консоль, `COMMAND_TIMEOUT` меняет тайм-аут,
`COMMAND_MAX_TIMEOUT` — верхний предел, `COMMAND_SHELL` — используемую оболочку.
Разрешённые чаты задаются тем же `FS_ALLOWED_CHAT_IDS`. Вопросы вида «как запустить»
не предоставляют инструмент консоли модели.

Состояние сервера: `http://127.0.0.1:5001/api/status`.
Веб-интерфейс: `http://127.0.0.1:5001`.

Проверки без реальных сообщений MAX:

```bash
.venv/bin/python -m unittest discover -s tests -v
```


## Приложения macOS и напоминания

Для разрешённого чата `<ID_ВАШЕГО_ЧАТА>` при `COMMANDS_ENABLED=1` доступны:

- «Запусти приложение Напоминания».
- «Создай напоминание с текстом Купить молоко».
- «Напомни завтра в 18:00 позвонить врачу».

Напоминание создаётся в списке по умолчанию. Срок используется только если указан
в сообщении; время соответствует часовому поясу Mac. Бот возвращает ID созданного
напоминания. Для управления Напоминаниями macOS может запросить разрешение
«Автоматизация» для процесса, запускающего бот. Разрешите доступ локально в
«Системные настройки → Конфиденциальность и безопасность → Автоматизация».
При отказе бот сообщает ошибку; не подтверждает создание без ID.
Запуск других приложений выполняется по их установленному имени.
Попытки операций сохраняются перед запуском: после сбоя они не повторяются автоматически.

В Bionic включите Settings → Local Models → Local Model API и проверьте порт 1234.
`LM_BASE_URL` должен соответствовать показанному адресу API. При отказе соединения
бот пробует `lms server start` (`LM_AUTO_START=0` отключает это поведение;
`LMS_CLI` задаёт путь CLI, `LMS_START_TIMEOUT` — тайм-аут запуска). Если CLI не может
подключиться к Bionic, включите API в самом приложении.

Пересылка новых уведомлений «Почты», Telegram, «Календаря» и «Напоминаний»
в чат `<ID_ВАШЕГО_ЧАТА>` включена. Проверка — каждые 5 секунд. Старую историю при первой
проверке бот пропускает. Mac и бот должны быть запущены, уведомления приложений —
включены в macOS. Доступен только текст, переданный приложением в Центр уведомлений.
Отключение: `NOTIFICATIONS_ENABLED=0`; диагностика: `/api/status` → `notifications`.

Голосовые: отправьте в MAX голосовое на русском (до 5 минут / 20 МБ). Бот вернёт
расшифровку и результат задания; распознавание работает локально через Whisper small.

Утренняя сводка: ежедневно в 08:00 по времени Mac, начиная со следующего утра,
в чат <ID_ВАШЕГО_ЧАТА>. Содержит события на день, просроченные напоминания и уведомления
за 24 часа. Разрешите помощнику чтение Календаря и Напоминаний, если macOS запросит.
Для проверки вручную отправьте `/summary`. Настройки и ограничения — в README.
